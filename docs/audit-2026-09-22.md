# 2026-09-22 代码与文档核查

## 本轮修复

- SSE（服务端推送事件）：收到模型结束信号后，待持久化与完成检查点写入成功才发送 done（完成）；流意外结束或保存失败返回 error（错误）。向客户端隐藏数据库及 SDK 异常原文。
- 医院接口：只读查询仅对网络及指定暂态 HTTP 错误重试；业务拒绝不重试，转诊写接口关闭自动重试；校验响应对象类型。
- A2A（智能体间通信）：业务失败、Agent 身份不符和无效回答结构均计入熔断，不进入最终汇总；失败响应不再承诺可安全重试。
- 熔断器：旧请求的迟到成功不能关闭新一代已打开的熔断状态；保留取消半开探测后的恢复能力。
- 会话：使用 JSON 二元组键避免分隔符碰撞，本地缓存读取返回副本，追加时刷新 TTL（过期时间）。
- JWT（签名令牌）：验证时强制要求过期字段。
- 观测与启动：指标使用路由模板，不包含实际患者 ID；数据库/Redis 就绪检查设置超时；启动部分子进程失败时清理已启动的子进程。
- 评测：向量校准的上游筛选与线上多意图线索规则一致；空评测集明确报错。
- 上传门禁：分别扫描工作区及 Git 索引内容，补充 LangSmith 和 GitHub 细粒度 Token（令牌）模式，报告位置而不打印密钥。
- 文档：修正执行顺序、安装顺序、账号示例、重试范围、检查点恢复能力及部署脱敏边界。
- Agent 上下文：明确无状态专科 Agent、协调器会话快照和统一写回边界；增加单次 Agent 运行内的重复工具调用指纹拦截及回归测试。
- 纯 ToB（面向机构）边界：十类意图、正则、提示词、原型、3,800 条合成数据、A2A 描述和院内工作台统一为医生、药师、医务管理人员及信息科场景；转诊协同、随访管理、用药审核和临床知识查询均按院内工作对象定义，院外服务请求在范围守卫处终止。
- 意图模型：从原始 `bert-base-chinese` 重新初始化十分类头并训练 v3，避免继承旧分类头语义；BERT 阈值校准为 0.95，向量阈值校准为 0.78，运行时校验模型标签集合。
- 意图回归：33 条纯 ToB 工程集严格匹配率、复杂任务标记准确率和 micro-F1（微平均 F1）均为 100%，0 个运行错误；独立合成测试、挑战和向量残余集按各自口径单独报告，不外推为临床准确率。
- 文档：话术文档补充英文术语及业务字段中文释义，并清理当时已移除能力的历史描述。简历不属于本仓库文档核查范围，后续版本应单独核对。

## 验证口径与仍需关注的边界

本轮完整上传预检通过：pytest（自动化测试）62 项通过，pip check（依赖一致性检查）通过，工作区与 Git 索引敏感模式扫描通过，Python 语法及配置项覆盖检查通过。测试有一项 LangChain MCP 适配器 Beta（测试阶段）警告，不是测试失败，升级依赖时需重新运行协议回归。

新增测试使用受控故障替身验证错误路径，不把这些测试称作医院真实接口联调。既有意图准确率和压测数字属于对应历史报告，本轮代码回归不等于重新完成模型评测或完整链路压力测试。

会话键格式变更后，旧格式 Redis 会话不会自动迁移，旧键按原 TTL 自行过期；正式升级前应安排会话切换窗口。MySQL 与 Redis 不是跨存储原子事务：一侧写入成功、另一侧失败时会返回错误，不能据此自动重放有副作用的业务。

关闭转诊自动重试不等于写操作具备幂等性。医院写入仍需双方约定幂等键、结果查询及人工确认；现有进程内熔断器不是全局分布式熔断。

HTTP 延迟指标测量响应创建时间，不是 SSE 全流耗时；模型首 token（词元）延迟和完整任务耗时应独立测量。

阶段 checkpoint（检查点）不是自动断点恢复。患者直接标识脱敏不是完整匿名化，院内接口鉴权、云端数据授权、日志出口审计和目标集群故障验证仍需部署环境核验。本次不对“所有真实输入都正确”或“生产无风险”作承诺。
