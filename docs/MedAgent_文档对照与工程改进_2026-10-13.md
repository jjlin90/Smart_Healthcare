## 已落实的代码改进

1. **任务选择和版本。** `task_mode` 支持自动、新任务、补充和更正。自动仅续接待澄清目标；明确新任务不继承业务历史；完整更正递增版本、替换旧业务输入，含糊更正追问。A2A 的签名范围和回包校验 `task_id/plan_version/step_id`。配置 Redis 后，MCP 执行前检查任务仍在执行且版本匹配。
2. **有界串并行。** 计划最多三个不同专科，依赖只能指向前序，非法结构回退确定性短链。独立只读就绪节点同批 `asyncio.gather`；有依赖的等待并传递脱敏工具依据；批准写动作时整个计划串行。同批普通失败等待在途调用结束后传播，不发送成功完成。
3. **关键参数和来源。** 模型提出参数，代码检查关键文本、占位值、列表、报告内容；药名必须出现在原始任务或可信用药档案，相互作用至少两药。记录原值、规范字段值、来源、请求、原文跨度、schema 与校验状态；当前原值与规范值相同，没有假称已做目录标准化。
4. **真实工具依据。** 小 Observation 保留脱敏内容，大结果标记截断并保留内容摘要标识。按十意图注册目标工具覆盖；空、错误、截断结果不确认完整覆盖，读病史不能代替查说明书。汇总收到脱敏 Observation，详细证据和参数来源写数据库审计，大记录分片以适应 TEXT 容量。
5. **一次只读纠错。** 仅当目标工具依据缺失，且未批准写动作、未出现写调用时，允许一次 LLM 重新识别。意图不变不循环，发生变化重新生成受控计划并递增版本，再次缺证据失败。普通网络/工具异常不会自动触发意图改写，写任务禁止自动重跑。
6. **医务人员反馈。** 工作台可选择期望意图并说明问题。服务端重新检查患者授权和原请求所属员工，保存为待临床复核记录，不自动修改模型、阈值或训练标签。当前只匹配该患者最近 100 条响应/拒识审计。


7. **统一剩余预算。** API 生成 deadline_at 并签名委托传播，专科和 MCP 拒绝过期执行，新调用取剩余时间与阶段上限的较小值；子令牌受父期限和任务期限约束。不承诺撤销已提交的外部写入。
8. **独立档案并发保护。** GET 返回 revision，PUT 必填 expected_revision，核对快照并以全部旧字段做 SQL 条件更新。冲突 409，缺版本 422；工作台重载并重建表单，档案和变更字段名审计同事务提交，无数据库迁移。

## 串行、并行和异步的口述例子

“查阿司匹林说明书，同时查糖尿病指南”：两个独立只读目标可在一个批次并发，收齐结果并核对两目标覆盖后汇总。

“先查指南，再依据指南审核用药”：计划把 DrugAgent 的 `depends_on` 指向前序 GuideAgent；后序只能在前序完成后收到脱敏依据。超过传递预算明确要求重新查询，不把截断原文当完整指南。

“审核后保存辅助记录”：本轮批准写动作的计划保持串行，写工具另过角色、患者授权及操作去重检查；结果未知先核对，不自动换计划重发。

这里的 async 是请求内并发和 SSE 展示。院内批量报告的长期后台队列、工作台刷新重放和节点持久恢复尚未实现，不能因为函数是 async 就说已拥有可靠后台任务。

## 仍需医院契约或进一步设计的部分

完整十意图的槽位 schema、医疗 NER、药品别名与单位标准化、逐字段继承和失效需要数据目录及专门评测。当前采用保守参数守卫与含糊请求追问。

最终参数级批准需增加预览、规范参数摘要、有期限批准及修改失效机制。现在只有动作级批准，不能将其当作医生已审核模型最终每个参数。独立档案编辑已补内容 revision 和 SQL 条件更新，旧表单冲突 409；这是内容快照校验，不是跨 HIS 的全局递增版本。

工具覆盖检查只证明对应类别有成功、非空的依据，不保证事实正确、工具足够细分或结论逐句被支持。完整临床语义审核、冲突裁决、指南版本和引用验收须有临床标注与责任人。

Redis 活跃版本能拦截随后到达的旧任务工具调用，不能原子撤销正在执行的外部写入。绝对 deadline 已传到 A2A/MCP 并限制新工具与医院 HTTP 调用；API 超时、断连或取消不保证远端写入停止。持续队列、节点恢复、SSE 事件重放和统一在途任务治理仍需独立实现。

本仓库没有正式医院接口凭据和生产验收。不能填造接口、开启医疗上云许可或编造业务收益；既有[生产验收](production-readiness.md)仍适用。独立 med_rag 的检索、切块和评测不计为本项目成果。
