## 清理结论

- 当前 `.env` 与 Kubernetes 配置均指向 `medical_intent_bert_tob_v3`，其标签为十类院内任务；旧目录 `models/medical_intent_bert` 和 `models/medical_intent_bert_v2` 含“挂号指引”等旧标签，且不在当前代码、配置或文档的运行引用中，已从本地 `models/` 删除。模型目录由 Git 忽略，本次没有删除或重训 v3。
- 本地 `artifacts/` 内七份含旧标签或旧模型路径的评测 JSON 已清理；README 中的回归命令统一写入 v3 报告路径。其余 v3 评测、压测和简历产物在本地保留；简历产物不再纳入当前 Git 索引。
- 已检查两版 HTML 简历的 Agent 项目段落：使用当前十类院内意图，明确写“3,800 条合成数据”和“236 条残余样本”，没有旧挂号类别或生产部署成果。进一步核对发现“33 条意图路由回归覆盖槽位澄清”的说法不准确；已改为 33 条覆盖单意图与多意图，槽位澄清另有自动化测试，并同步两版 PDF 与简历生成脚本。
- 训练脚本默认输出目录已改为 v3，避免未指定 `--output` 时重新生成旧路径。范围守卫现在会拦截同时包含患者自助预约与转诊单的请求，防止自助服务词被转诊词掩盖。这是保守拒识：若今后要处理院内预约业务，应单独设计员工权限与意图，不应复用患者自助入口。
- 当前合成数据中仍有“我想了解”“用通俗的话说明”等自然语言模板；这些词本身不构成患者登录、挂号或支付能力。直接修改训练集而不重新训练并复评 v3 会造成文档、数据、权重和指标版本不一致，因此保留现役数据与权重，并在面试中明确其合成数据属性。

## 文档口径修正

- 应用服务可在院内部署，主模型目前通过 SiliconFlow 云端接口调用，整条推理链不能称为完全私有化部署。
- BERT 训练数据是院内任务的**合成文本**，不是医院真实业务数据。工程回归和合成测试分数不代表临床准确率。
- 转诊工具会先调用 HIS 写接口，再把本地记录标记为“待医生确认”；当前没有写入前的人工审批。`save_patient_history` 每次调用还会追加审计，不能以 MCP 的 `idempotentHint` 声称完全幂等；已去掉该提示。
- 单次专科任务内的重复工具指纹拦截已经实现；执行中自动重新规划、总任务截止时间、跨请求写入幂等、患者授权撤销后对内部 A2A/MCP 调用的再次鉴权仍需补充或联调。
- 50 条分布外样本用于 BERT 阈值拒识评测；范围模型异常时停止工具调用是另一组测试，不能混称为一项结果。医院接口未提供时，相关功能会明确失败，不能宣称已经完成医院联调。
- 已修复重复、误译和连在标题后的正文，补充常用术语中文含义；扩展题中的设计方案继续与当前实现区分。

## 本轮验证

- `python -m pytest -q`：64 项通过，另有 LangChain MCP 适配器处于 Beta 阶段的警告。
- `python scripts/check_config.py`：本地核心配置检查通过；医院系统配置仍不完整，未运行严格生产联调验收。
- 33 条工程回归：严格匹配率、复杂任务标记准确率、micro-F1（微平均 F1）均为 100%，32 条由正则层完成、1 条由向量层完成；报告在 `artifacts/intent_eval_audit_20260924.json`。
- BERT v3 的 1,000 条合成单意图测试集：`0.95` 阈值覆盖率 98.8%，接受样本准确率 100%。400 条挑战集中的 100 条单意图：原始首选类别准确率 60%，阈值覆盖率 24%，接受样本准确率 100%；50 条分布外样本全部拒绝。
- BGE-M3 向量层在同一挑战集上，以当前上游路由和阈值计算，有 236 条到达向量层；`0.78` 阈值接受 10 条且均正确。这里是在已选定阈值上的复核，不把挑战集作为重新调参集。

## 尚不能据此声称的结论

本次核查和自动化测试不能证明真实医院接口已联调、临床效果合格、系统已生产上线，或所有自然语言请求都能正确拒识。进程内熔断器目前把保护范围内的业务异常也计为失败；业务拒绝虽然不自动重试，仍可能累计熔断次数。内部 A2A/MCP 的独立服务认证和写操作幂等需要生产环境补强。
