## 正确理解写操作结果

以下操作状态与重放规则适用于三个 MCP 写工具。`request_id` 由客户端为一次业务任务生成，并在核对/同任务重放时保持一致。每个员工、请求、工具对应一组参数，可通过 `GET /api/operations/{request_id}` 查询：

- `completed`：本地记录已保存工具完成结果；重放相同参数返回保存结果。
- `pending`：仍在执行，或进程在占位后退出；先核对，不重新创建任务绕过占位。
- 三种写工具在占位前校验参数；确定的参数错误不会留下占位，修正后可使用同一请求标识重试。
- `unknown`：通过参数预检后，调用、结果保存或确认失败，动作可能已经发生；需要人工对照 HIS 编号或本地数据库及审计。不能仅按异常类型判定未执行，也不自动重试。

转诊适配层发送 `require_confirmation=true`，要求响应包含非空 `referral_id`，且 `status` 为 `pending_confirmation`、`draft` 或“待医生确认”。医院契约若不同，应在适配层映射并增加契约测试；不能用本地自增编号替代缺失的远端创建证据。该字段要求不证明 HIS 实际遵循审批规则，必须联合验收。

两个临床记录写工具的动作级勾选不绑定模型最终参数。独立转诊草稿通过 `POST /api/referral-drafts` 提交医生确认的患者、科室和原因；`ReferralDraftService` 将这些参数的摘要写入签名委托，MCP 执行前重算并比对，变更参数会被拒绝。转诊不由聊天或临床专科创建，不增加第四个智能体。接口返回 502 表示草稿尚未确认完成，既可能尚未执行，也可能已发生但结果未收到；应使用原请求标识查询操作状态并核对医院结果，不能把该响应直接判为已执行或未执行。

下游成功、本地确认失败不能靠数据库回滚撤销。人工核对前不得直接删 `tool_executions` 行、换请求标识或自动重试。跨 MySQL/Redis 没有分布式事务，阶段状态也不是可重放事件日志。

独立档案编辑由员工直接提交工作台表单，不使用 `approved_actions`，不生成 `ToolExecution`，操作查询接口也不记录这次保存。成功响应在档案和审计共同提交后返回；提交失败的回滚已有测试。若响应丢失，仍需重新读取档案并核对 `profile_updated` 审计，不能仅凭客户端报错认定未保存。当前审计记录员工、读取的内容 revision 和变更字段名，未保存全部前后值；医院还需确认是否满足其追溯要求。

## 发布前可复现检查

在项目根目录、已配置的 Python 环境执行：

```powershell
python -m pip install -r requirements-dev.txt -c constraints.txt
python -m pip check
python scripts/check_config.py --strict
python -m pytest -q
python scripts/preflight_git.py
```

当前数据库支持范围：本地默认及测试使用 SQLite；生产配置校验仅接受 `mysql+aiomysql://`，Docker Compose 清单包含 MySQL 8.4 服务，运行依赖声明 aiomysql；K8s 的 Secret 仅保留 DATABASE_URL 占位值，需要部署方注入有效的 MySQL DSN，清单本身没有提供可用数据库连接。PostgreSQL 与 MongoDB 尚未接入，不能与 MySQL 并列描述为本项目可直接选择的生产后端。若新增 PostgreSQL，需同步调整生产校验、驱动依赖与数据库迁移，并在目标数据库验证事务、并发及部署行为。数据库升级应先在目标 MySQL 版本的备份副本演练，再由发布流程执行；SQLite 迁移测试、配置校验通过或驱动已声明，均不代替目标 MySQL 的数据及锁行为验证，也不表示已经完成生产部署。

DSN 是数据库连接串，用来说明连接目标及使用的数据库方言、驱动。`mysql+aiomysql://` 表示 MySQL 配合异步驱动 aiomysql 的连接前缀，本身不是完整可用的连接地址；还要按目标环境配置主机、库名及认证信息。K8s 中的 `DATABASE_URL: REPLACE_ME` 是待部署方替换的占位值，不能直接用来启动生产服务。填入连接串后，仍需做配置校验和真实连通性验证。

`constraints.txt` 固定已测试的直接依赖，不是完整传递依赖哈希锁。LangChain MCP 适配器仍标记为测试阶段，当前 WSGI 桥接还有弃用提示；已用本地协议测试覆盖，但升级 Starlette、FastMCP、LangChain 或 python-a2a 前必须重新做兼容验证。供应链扫描、镜像摘要和完整软件物料清单仍需目标构建流程提供。

## 2026-10-13 补充：时间预算与档案冲突

签名绝对 deadline_at 传至 A2A/MCP，分派与新工具调用用剩余预算，医院 HTTP 使用剩余时间与单次上限的较小值。时钟同步、真实下游取消和未知写结果核对仍需医院验收。

档案 GET 返回内容 revision，PUT 必填 expected_revision。服务端同时做快照核对与原字段 SQL 条件更新，冲突 409，不写审计成功记录；工作台支持重载档案并重建表单。这是内容快照保护，不是跨 HIS 全局版本或分布式锁。旧客户端缺该字段将返回 422，应更新调用方式。

## 2026-10-13 复核：生产任务围栏

生产 A2A/MCP 验证拒绝缺少 task_id、conversation_key、plan_version、step_id 或 deadline_at 的签名令牌。MCP 执行前要求 Redis 并检查 checkpoint 的 started 阶段及任务版本；Redis 不可用或缺配置时失败，不降为本地放行。开发环境无 Redis 的旧委托与 TTL 模式只用于本地联调，不能证明跨进程任务有效性。检查后开始的外部调用仍可能与任务失效并发，不能宣称能原子撤销医院写入。
