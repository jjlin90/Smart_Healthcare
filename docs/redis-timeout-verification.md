|---|---|
| 请求超时 120 秒时的锁 TTL | 180 秒 |

## 超时与令牌边界

- API 整轮预算默认 120 秒；专科串行执行，没有按剩余时间重新分配预算，也未向专科传播统一的绝对截止时间。
- A2A 客户端和专科自身超时各默认 120 秒，专科计时从自身执行开始。WSGI 等待默认 125 秒，超时调用 `pending.cancel()`，但不保证正在执行的阻塞操作立即终止。
- 新签发的根 A2A 委托默认有效期为签发时刻起 150 秒。本轮修复：从已验证父委托签发 MCP 子令牌时，到期时间不超过父令牌；父令牌过期后拒绝再次签发。
- 令牌有效期不是跨服务请求截止时间。专科可能在整轮请求较晚阶段才启动，故不能把 API 超时后的剩余执行窗口固定描述为 30 秒。令牌过期限制后续授权，不会自动撤销已经授权并开始执行的 HTTP 请求或数据库写入。
- 本地取消不等于远端回滚。未知写结果仍需按请求标识检查操作表并核对 HIS；不能换标识盲目重复写入。
- SSE 错误事件依赖连接仍可写。客户端断连或发送背压期间超时，不保证最后一条错误事件可达；客户端必须把未收到 `done` 当作未确认完成。

当前全量测试 127 项通过，包含 3 项 Redis 客户端分支测试，以及父子令牌有效期和过期拒签测试。真实 Redis 验证为独立集成验证，不混入 pytest 数量。
