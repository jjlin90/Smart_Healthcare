# MedAgent 项目理解指南：先把一次请求讲顺

这份是速读版，面试讲稿和全部题目集中在[完整讲稿与题库](MedAgent_AI_多Agent项目话术.md)。先读懂下面六段，再按追问查对应题目。

## 1. 先记住业务定位

我做的是 ToB（面向机构）的院内临床辅助工作台，给医生、药师和医务管理人员使用。它把药品、指南、检验等需求从自然语言变成受控工具任务，再整理有依据的辅助结果供临床复核。患者是被授权访问的数据对象。

## 2. 顺着一次查询理解整条链

医生登录并选择患者，工作台把问题发到聊天流式接口，也就是 `POST /api/chat/stream`。FastAPI（接口服务框架）先验 JWT（身份令牌），再查实时员工状态、角色与患者授权。主协调器依次处理急症、业务范围、意图和缺失参数；缺药名先问药名。

普通药品查询交给 DrugAgent（药品智能体），协调器用 A2A（智能体间通信）传任务和短期委托，专科重新查可信档案，用 MCP（模型上下文协议）调药品工具。执行前再次验权限；有成功工具证据且没有工具失败，才接受专科结论。最后汇总出字，保存咨询、审计与会话，发 done（完成事件）后页面确认完成。

理解顺序就是：**先确认能查谁，再确定查什么，参数齐全才查，有证据才答，保存完成才确认。**

## 3. 理解“四层、十类、三个、十四个”

四层路由是正则、BERT（双向编码器分类模型）、BGE-M3（文本向量模型）和云端 LLM（大语言模型）。前层接收通常就结束，用较低成本处理明确请求，剩余复杂表达再兜底。BERT（双向编码器分类模型）单标签默认阈值 0.95，向量默认 0.78；多任务候选分差 0.04 不适用于所有单任务歧义判断。

十类是业务目标，三个是专科执行者，十四个是注册工具。SymptomAgent（症状智能体）管症状、分诊与转诊，DrugAgent（药品智能体）管药品与用药审核，GuideAgent（指南智能体）管指南、知识、检验、报告和随访。多个业务目标可以归同一专科，工具按职责白名单开放。

## 4. 理解谁规划、谁行动

Planning（任务规划）选择需要的专科，服务端校验计划最多三步、不漏专科、不加无关或重复专科。当前串行执行，前步结果不自动喂给后步；单标签复杂任务也可规划。

ReAct（推理与行动）是专科内部根据 Observation（观察结果）继续选工具的循环。模型与工具各最多六次，同工具同参数重复调用会被拦截。A2A（智能体间通信）负责交任务，MCP（模型上下文协议）负责接工具，Function Calling（函数调用）负责模型选名称和参数，权限始终由代码校验。

## 5. 理解三个最容易混淆的状态

**有文字不等于完成。** SSE（服务器发送事件）的 delta（增量文字）只是汇总增量，done（完成事件）才确认保存结束。只有最终汇总原生流式，前面的路由与工具仍要等待。

**超时不等于没写入。** 三个写工具本轮确认后才开放，先校验参数、登记 pending（执行中或待核对），再执行。同员工、同请求、同工具已完成则复用，unknown（结果未知）不重发，要核对 HIS（医院信息系统）。当前本地幂等不能承诺下游恰好一次。

**阶段记录不等于可自动恢复。** Redis（共享内存存储）保存近期对话与阶段，MySQL（关系数据库）保存业务记录，二者没有跨系统原子事务。会话按员工、患者和会话隔离，整轮锁防交错；目前没有任意步骤续跑或精确 SSE（服务器发送事件）续传。

## 6. 理解项目成绩与实际支持范围

可以讲三个专科、十四个工具、十类意图和请求级权限控制；3,800 条合成数据用于工程训练与评测，33 条固定路由回归严格匹配与 Micro-F1（微平均 F1）均 100%。[README 测试记录](../README.md)记载，2026-09-30 共 127 项自动化测试通过；验证范围与历史口径见[完整讲稿的评测部分](MedAgent_AI_多Agent项目话术.md#10-评测成果与上线状态数字怎么讲)。

完整链路主模型仍用云接口。检验需要提供数值，真实医院工具未配置就明确失败；影像识别、独立 EMR（电子病历系统）连接器、医院正式上线和临床收益分别需要实际实现或验收证据。健康接口历史约 401 RPS（每秒请求数）只说明入口测试范围。

**面试收尾可直接说：** 这个项目的重点是把自然语言需求变成可授权、可执行、可复核的工具链。我通过分层路由、受控规划、工具白名单和写操作状态管理，让成功有证据，失败有状态，排障有记录。
