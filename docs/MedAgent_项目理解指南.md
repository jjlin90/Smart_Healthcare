# MedAgent(医疗智能体项目) 项目理解指南：先把一次请求讲顺

最近核查：2026-10-13。先读本页，再按[完整讲稿与题库](MedAgent_AI_多Agent项目话术.md)展开追问；新增[全部 14 份文档逐题适配](MedAgent_逐题适配/README.md)及[工程改进对照](MedAgent_文档对照与工程改进_2026-10-13.md)。亲历分工按实际情况使用。

## 1. 先记住业务定位

这是面向医院医生和药师的临床辅助工作台，把药品、指南、检验等自然语言需求变成受控工具任务，再整理辅助结果供临床复核。员工只能访问获授权的患者；医务管理员有医院级只读范围，当前没有独立管理后台。

价值目标是减少切换查询入口、重复填写已有患者资料和手工整理。当前完成的是本地工程验证，真实医院接入、临床效果和业务提效仍待验收。衡量提效要比较同类任务从查询到完成复核的总耗时，并计入失败重做与人工纠错；没有业务基线时不报提效比例。

## 2. 顺着一次查询理解整条链

以“查询阿莫西林说明书”为例：员工登录、选择授权患者后，工作台发送 `POST /api/chat/stream`(提交请求；应用程序接口)。入口验证 JWT(身份认证令牌)，并从数据库读取当前员工状态、角色与患者授权。

协调器依次做独立安全检查、范围判断、三路意图融合和典型缺信息检查。当下急症优先提示院内急救；不确定暂停普通业务。范围外结束，混合请求只保留核对过的医疗原文。任务选择区分新请求、补充和更正，拒绝含糊更正直接执行；模型工具参数还要经过关键槽位校验和药名依据检查。尚未实现完整十意图抽取器或医疗 NER(命名实体识别)。

药品任务通过 A2A(智能体间通信协议) 交给 DrugAgent(药品智能体)。专科重新鉴权读取档案，按白名单、批准动作和父委托交集绑定 MCP(模型上下文协议) 工具。每个意图必须有对应成功且非空、未截断的工具依据，病史读取不能代替药品说明书；有工具失败不确认成功。只读依据覆盖不匹配最多一次语义复核并重新路由，写动作不自动重跑。

正常流式路径把专科回答、状态与脱敏工具 Observation(工具观察结果) 交给汇总模型。详细证据、参数来源和任务版本保存在授权审计里，SSE(服务器推送事件) 只展示规定事件。工程覆盖校验不能证明医学结论正确，仍需临床复核。入口完成持久化后才发送 `done`(完成事件)：**核验访问对象 → 确定任务 → 检查参数 → 调真实工具 → 核对目标依据 → 汇总复核 → 保存并确认。**

## 3. 理解“三路融合、十类、三个、十四个”

三路是 Regex(正则表达式)、十标签 BERT(双向编码语言模型)/Sigmoid(逐标签概率) 与 BGE-M3(多语言多粒度多功能嵌入模型)。规则命中也继续执行本地模型；融合使用各通道自身阈值，不比较原始分数大小，也不按多数投票。规则或向量提出 BERT(双向编码语言模型) 未接受的标签、阈值边界、否定、模型不可用或可能漏任务时，交给 LLM(大语言模型) 复核；复核失败停止路由。[融合机制](intent-fusion.md)。

十类是模型兼容标签，三个是临床执行专科，十四个是注册工具。SymptomAgent(症状智能体) 负责症状辅助评估、风险提示、疾病信息与科室建议，不创建转诊草稿；DrugAgent(药品智能体) 负责药品与用药审核；GuideAgent(指南智能体) 负责指南、知识、检验、报告与随访。九类临床辅助标签映射到专科；旧“转诊协同”标签对外称“转诊草稿辅助创建”，协调器只提示医生确认入口，不进入专科计划。独立 ReferralDraftService(转诊草稿业务服务) 在医生确认参数后创建草稿，是业务服务，不是第四个智能体。随访没有排期、提醒工具，影像报告没有图像分析，指南调用外部服务而非本仓库自建 RAG(检索增强生成)。

十四个工具中十一个调用外部接口，三个读写项目数据库，其中共有三个写工具。注册和权限测试不能证明医院接口已接通。检验工具使用请求提供的项目、数值、单位和参考范围，调用 LIS(检验信息系统) 解释接口；没有从 LIS(检验信息系统) 自动拉取整份患者检验记录的工具。

**三个专科默认调用同一个云端大语言模型。** 它们分别运行三个 A2A(智能体间通信协议) 服务，各自创建工具循环，维护本轮消息、工具结果、计数和去重记录。BERT(双向编码语言模型) 与 BGE-M3(多语言多粒度多功能嵌入模型) 是本地路由模型；规划、专科执行、汇总和按需语义复核使用配置的云端主模型。应用可院内部署，整条推理链当前仍有云调用。

## 4. 理解谁规划、谁行动

`MedicalCoordinator`(医疗主协调器) 是流程调度程序。复杂任务时，`Planner.plan`(规划器；计划) 调用云模型生成最多三步计划，代码检查必要专科是否完整、无关或重复。结构不合法回退为受控计划，网络请求失败仍按失败结束。多个意图归同一专科时只调用该专科一次；用药审核等复杂单意图也可能先规划。

Planning(任务规划) 是协调器内部角色，最多三个专科的依赖计划：独立只读步骤并行，有前序依赖的步骤串行并传递脱敏依据；批准写动作时整体串行。非法依赖回退确定性短链。仅有一次只读覆盖纠错重路由，没有持久后台队列或任意节点断点恢复。

ReAct(推理与行动交替) 是每个专科内部的“模型提出工具调用 → 程序校验执行 → 结果回填 → 决定下一步”循环。每个专科任务的模型和工具调用分别最多六次，同工具同参数重复调用被拦截。A2A(智能体间通信协议) 传任务，MCP(模型上下文协议) 连接工具，Function Calling(函数调用) 表达模型调用请求；实际权限由代码校验。

专科重新读取可信患者档案，维护各自本轮执行循环。新任务隔离旧历史；待澄清续接只组合原任务和当前补充。依赖节点额外读取有界前序工具依据，协调器汇总，入口统一写回跨轮会话。A2A(智能体间通信协议) 回包须匹配任务、版本和步骤，配置 Redis(内存键值数据库) 时 MCP(模型上下文协议) 执行前检查任务活跃版本。

## 5. 理解写入、持久化与完成状态

三个 MCP(模型上下文协议) 写工具分别是病史保存、辅助材料保存和转诊草稿创建。聊天 approved_actions(本轮批准动作) 只批准前两项，仍是动作级确认。转诊改走独立 POST(提交请求) /api(应用程序接口)/referral(院内转诊)-drafts：医生填写患者、目标科室和原因并明确确认，服务签发仅允许 generate_referral(创建转诊草稿) 的限时委托，绑定 confirmed_arguments_sha256(医生确认参数摘要)；MCP(模型上下文协议) 重新核对业务服务身份、最终参数、医生角色与患者授权。症状智能体和聊天均无权创建草稿，不代表完整转诊协同已经实现。

写工具先校验参数，再按“员工、请求标识、工具名”登记唯一操作记录。相同键与参数已完成则复用结果；参数冲突、`pending`(待处理) 或 `unknown`(未知) 则阻止重发。`GET /api/operations/{request_id}`(读取请求；应用程序接口；请求标识) 查询本地状态，医院实际结果另行核对。换请求标识仍可能重复，不能称为全局恰好一次。

档案编辑走独立 `PUT /api/patients/{patient_id}/profile`(更新请求；应用程序接口；患者列表；患者标识；患者档案)，医生或药师填写并保存。先 GET(读取请求) 读取 `revision`(修订号)，PUT(更新请求) 必须携带 `expected_revision`(预期状态修订号)；后端核对内容并用原字段 SQL(结构化查询语言) 条件更新，旧版本返回 409，重载并核对后再保存。档案与修改字段名审计同事务提交，不使用聊天批准动作或 MCP(模型上下文协议) 操作状态表。

关系数据库保存业务记录；Redis(内存键值数据库) 保存近期历史、阶段记录与整轮锁，未配置时使用进程内过期缓存。会话键包含员工、患者和会话标识。阶段记录可定位中断位置，不能恢复任意模型工具循环。数据库先提交、会话后保存，两者没有跨存储事务。

**`delta`(增量内容) 是暂存片段，`done`(完成事件) 才是本轮分支的完成确认。** 汇总必须有实际内容并以 `finish_reason=stop`(生成结束原因；停止) 正常结束，空白、仅免责声明、截断、过滤和缺少结束标记均失败。专科拒绝空回答和明确的非正常结束，但适配器缺少结束元数据时无法只靠该字段确认完整性。汇总失败不会进入正常答复保存，也不会撤销此前完成的 MCP(模型上下文协议) 写工具。数据库提交后 Redis(内存键值数据库) 失败，也不会回滚数据库。澄清或拒识可发送 `done`(完成事件)，但不表示原医学任务已完成。
