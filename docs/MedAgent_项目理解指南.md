# MedAgent 项目理解指南：先把一次请求讲顺

这份是速读版，用下面六节理解当前实现并组织主动讲解；具体边界和扩展方案在[完整讲稿与题库](MedAgent_AI_多Agent项目话术.md)的对应追问中展开。数字保留评测对象与样本数，讲解时按需要选择内容。

面试项目描述按五点组织：**商业价值 → 技术选型、架构与流程 → 至少三个具体问题 → 个人职责 → 优化策略与结果数据。** [完整讲稿](MedAgent_AI_多Agent项目话术.md)第一部分第 0 节已补充可口述版本、四个问题案例、职责与交付物，以及优化结果的来源。先用五点组织整体介绍，再用下面六节理解代码；个人职责按实际参与情况使用。

## 1. 先记住业务定位

我做的是 ToB（面向机构）的院内临床辅助工作台，主要服务医生和药师。它把药品、指南、检验等需求从自然语言变成受控工具任务，再整理有依据的辅助结果供临床复核。系统按患者授权限制员工可访问的资料；医务管理员使用医院级只读范围查看患者信息并发起查询。

使用价值是减少切换查询入口、重复填写已保存的患者资料和手工汇总结果的步骤，让医生和药师把时间用于核对依据、复核结果。当前完成本地工程验证，真实医院接入及试点验收仍待完成；具体能节省多少时间，需要对比同类任务的总耗时、操作次数与结果质量，不能用路由准确率或健康接口吞吐量代替业务提效数据。

## 2. 顺着一次查询理解整条链

医生登录并选择患者，工作台把问题发到聊天流式接口 `POST /api/chat/stream`。入口先验证 JWT，再查询员工当前状态、角色和患者授权。协调器随后检查急症、判断业务范围、识别意图，并对典型缺信息请求追问，例如未说明药名或报告内容。范围守卫判断“是否属于支持的业务”，权限校验判断“是否允许访问”，二者职责不同。

普通药品查询交给 DrugAgent。协调器用 A2A 传任务和短期委托，专科重新读取可信患者档案，并按专科白名单、本轮批准动作与父委托工具范围的交集绑定 MCP 工具；子委托只能收窄父工具范围，不能扩大范围或更换专科；工具服务执行前再核验授权。MCP 返回 `isError` 时会计为工具失败；专科必须有成功工具证据且没有工具失败，才能返回正常结果。随后汇总模型生成回答供临床复核，入口保存本轮记录并发送 `done`，页面才确认完成。

理解顺序就是：**先确认能查谁，再确定查什么，参数齐全才查，有证据才答，保存完成才确认。**

## 3. 理解“四层、十类、三个、十四个”

四层意图路由依次是正则、本地 BERT、本地 BGE-M3 和云端大语言模型，某层满足接受条件后通常就返回。BERT 只预测一个标签，最高分默认至少为 0.95，且没有多任务线索时才接受；BGE-M3 比较问题与带意图标签的示例句，相似度默认至少为 0.78。出现多任务线索时，向量层最多保留三个达到阈值且与最高分相差不超过 0.04 的意图；只保留一个则继续交大模型核对。这些分数含义不同，不是医学正确率，也不能跨层比较大小。

十类是系统识别的业务目标，三个是分别执行专科任务的 Agent，十四个是注册工具。SymptomAgent（症状智能体）管症状、分诊与转诊，DrugAgent（药品智能体）管药品与用药审核，GuideAgent（指南智能体）管指南、知识、检验、报告和随访。多个业务目标可以归同一专科，工具按职责白名单开放，并按本轮授权进一步过滤。

其中，“检验结果辅助解读”主要针对一项或一组检验指标，“检查报告辅助解读”指整份报告的综合解读。同一份肝功能报告，询问某个指标和要求梳理整份报告，可能对应不同意图；两者都归 GuideAgent，分类依据是请求的解读范围，并非“化验”与“影像”两个互斥类别。

十四个工具中，十一个调用外部接口，三个读写项目数据库。指南工具把疾病和关键词交给配置的外部指南服务；检验工具把请求提供的项目、数值、单位和参考范围交给 LIS（检验信息系统）解释接口。意图分类决定业务目标，专科调用本轮获准的工具执行任务。

**三个 Agent 默认使用同一个云端大语言模型。** 它们都读取 `SILICONFLOW_MODEL` 配置，分别在三个 A2A 服务中执行任务。每个专科任务创建自己的工具调用循环，使用各自的专科名称、任务、工具白名单和本轮消息记录。因此，“同一模型”说明底层模型配置相同，“多 Agent”说明有多个分工执行的程序，二者可以同时成立。本地 BERT 和 BGE-M3 负责意图路由，云端模型负责专科执行、规划与汇总。

## 4. 理解谁规划、谁行动

`MedicalCoordinator` 负责流程检查、任务分派和结果收集。复杂任务时，`Planner.plan` 调用与专科相同配置的云端模型生成任务列表，后端检查专科是否完整、相关且不重复，计划最多三步。Planning Agent 在这里指协调器中的规划角色，不是另外部署的服务。当前专科按顺序执行，前步结果不会自动传给后步；用药审核等单意图复杂任务也可能先规划。

ReAct（推理与行动）是每个专科任务内部的工具循环：模型提出工具名称和参数，服务端校验并执行工具，把结果作为 Observation（观察结果）回填到该专科的消息记录，再调用模型决定继续查询或回答。每个专科任务的模型与工具调用各最多六次，同工具同参数重复调用会被拦截。A2A（智能体间通信）负责协调器向专科交任务，MCP（模型上下文协议）负责专科连接工具服务，Function Calling（函数调用）负责模型提出工具调用请求，权限始终由代码校验。

专科返回结果后，流式接口再调用 `Planner.synthesize_stream`，让同一配置的云端模型根据收集到的专科结果生成最终回答。规划、专科执行和汇总是分别发起的模型请求，承担不同职责。

## 5. 理解会话、写入与完成状态

专科的本轮执行状态分别维护，包括模型消息、工具结果、调用计数和去重记录。它们可以收到同一员工、同一患者会话的历史快照，也会读取同一患者的可信档案。协调器收集各专科返回的结果，业务入口统一保存本轮会话：专科各自维护执行状态，入口统一维护跨轮历史。

**增量文字与完成确认不同。** `delta` 只是回答片段，`done` 表示本轮分支要求的持久化已完成。正常工具查询保存咨询、审计和会话；澄清或拒识会跳过部分保存，不表示用户的医学查询已完成。前面的路由和专科工具需要先执行完，最终汇总才原生流式出字。

**写入超时可能发生在成功之后。** 三个 MCP 写工具经本轮动作级确认和权限校验后，先登记 `pending` 操作记录，再执行。对于同一员工、同一请求、同一工具，参数相同且操作已完成时复用结果；参数不同则拒绝；状态为 `pending` 或 `unknown` 时阻止重发，需要核对实际写入目标。`GET /api/operations/{request_id}` 查询本地 MCP 写工具状态，医院侧结果另行核对。

**档案编辑是另一条写入路径。** 医生、药师在工作台表单中编辑已授权患者的资料，点击保存后调用 `PUT /api/patients/{patient_id}/profile`。表单状态按患者隔离，切换患者会清除前一患者未保存的输入。接口校验身份、写角色、患者授权和字段约束，在同一数据库事务中保存档案与审计记录。这条直接编辑路径以档案和审计记录核对结果，不使用聊天的动作批准字段，也不进入 MCP 工具操作状态表。

**业务记录与近期会话分别保存。** 关系数据库保存业务记录，生产参考使用 MySQL，本地默认可用 SQLite。配置 Redis 后，近期对话、阶段记录和会话锁存入 Redis；未配置时使用进程内过期缓存，本地执行锁容量为 1000 个，容量满时拒绝新任务，避免驱逐活动会话锁。入口先保存数据库业务记录，再写会话与阶段记录；阶段记录用于追踪请求进度，会话锁用于控制同一会话的并发请求。

## 6. 理解项目成果与验证口径

可以讲三个专科、十四个工具、十类意图和请求级权限控制。3,800 条合成数据用于工程训练与评测；33 条固定路由回归的意图集合严格匹配率与 Micro-F1 均为 100%。[README 测试记录](../README.md)记载，2026-10-07 本轮完整回归实测 170 项自动化测试通过，覆盖权限、协议、档案编辑校验与事务回滚等工程场景。详细口径见[完整讲稿的评测部分](MedAgent_AI_多Agent项目话术.md#10-评测成果与上线状态数字怎么讲)。

历史 BERT 与向量摘要保留本机 CRLF 数据集的 `dataset_sha256`，另以 `repository_dataset_sha256` 记录仓库 LF 文件；核对克隆后的数据集时使用后者。本机保留的两组 BERT 报告已按原始字节校验，均匹配 `source_report_sha256`；每组有两份同字节副本，哈希能确认内容一致，不能判定哪份是最早生成的文件。它们是被忽略的本地产物，未随仓库提供，因此仅凭克隆不能独立验证来源报告。具体范围见 [README 模型与指标复核](../README.md#克隆后的模型准备与指标复核)。

**被追问“具体目标是多少”时使用，开场不主动讲：** 暂定试点目标是在结果完整性不降低、人工纠错量不增加的前提下，将同类查询任务从开始查询到完成复核的总耗时降低 20%。20% 是待验证的规划目标，没有业务实测依据，不是当前成果，也不代表整体诊疗效率；取得基线后再评估是否可达。测量方式与假设算例见[完整讲稿的一分钟开场及追问](MedAgent_AI_多Agent项目话术.md#1-一分钟开场做什么为什么做重点是什么)。

**面试收尾可直接说：** 这个项目的重点是把自然语言需求变成可授权、可执行、可复核的工具链。我通过分层路由、受控规划、工具白名单和写操作状态管理，为正常查询保留工具依据，为失败请求记录处理状态，让排障能追溯到具体调用。临床结论仍由医务人员复核。
