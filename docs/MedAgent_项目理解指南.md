# MedAgent 项目理解指南：先把一次请求讲顺

最近核查：2026-10-13。先读本页，再按[完整讲稿与题库](MedAgent_AI_多Agent项目话术.md)展开追问；新增[全部 14 份文档逐题适配](MedAgent_逐题适配/README.md)及[工程改进对照](MedAgent_文档对照与工程改进_2026-10-13.md)。亲历分工按实际情况使用。

## 1. 先记住业务定位

这是面向医院医生和药师的临床辅助工作台，把药品、指南、检验等自然语言需求变成受控工具任务，再整理辅助结果供临床复核。员工只能访问获授权的患者；医务管理员有医院级只读范围，当前没有独立管理后台。

价值目标是减少切换查询入口、重复填写已有患者资料和手工整理。当前完成的是本地工程验证，真实医院接入、临床效果和业务提效仍待验收。衡量提效要比较同类任务从查询到完成复核的总耗时，并计入失败重做与人工纠错；没有业务基线时不报提效比例。

## 2. 顺着一次查询理解整条链

以“查询阿莫西林说明书”为例：员工登录、选择授权患者后，工作台发送 `POST /api/chat/stream`。入口验证 JWT，并从数据库读取当前员工状态、角色与患者授权。

协调器依次做独立安全检查、范围判断、三路意图融合和典型缺信息检查。当下急症优先提示院内急救；不确定暂停普通业务。范围外结束，混合请求只保留核对过的医疗原文。任务选择区分新请求、补充和更正，拒绝含糊更正直接执行；模型工具参数还要经过关键槽位校验和药名依据检查。尚未实现完整十意图抽取器或医疗 NER。

药品任务通过 A2A 交给 DrugAgent。专科重新鉴权读取档案，按白名单、批准动作和父委托交集绑定 MCP 工具。每个意图必须有对应成功且非空、未截断的工具依据，病史读取不能代替药品说明书；有工具失败不确认成功。只读依据覆盖不匹配最多一次语义复核并重新路由，写动作不自动重跑。

正常流式路径把专科回答、状态与脱敏工具 Observation 交给汇总模型。详细证据、参数来源和任务版本保存在授权审计里，SSE 只展示规定事件。工程覆盖校验不能证明医学结论正确，仍需临床复核。入口完成持久化后才发送 `done`：**核验访问对象 → 确定任务 → 检查参数 → 调真实工具 → 核对目标依据 → 汇总复核 → 保存并确认。**

## 3. 理解“三路融合、十类、三个、十四个”

三路是 Regex、十标签 BERT/Sigmoid 与 BGE-M3。规则命中也继续执行本地模型；融合使用各通道自身阈值，不比较原始分数大小，也不按多数投票。规则或向量提出 BERT 未接受的标签、阈值边界、否定、模型不可用或可能漏任务时，交给 LLM 复核；复核失败停止路由。[融合机制](intent-fusion.md)。

十类是业务目标，三个是执行专科，十四个是注册工具。SymptomAgent 负责症状、分诊和转诊；DrugAgent 负责药品与用药审核；GuideAgent 负责指南、知识、检验、报告与随访。十类意图不等于十条完整业务闭环：随访没有排期、提醒工具，影像报告没有图像分析，指南检索调用外部服务而非本仓库自建 RAG。

十四个工具中十一个调用外部接口，三个读写项目数据库，其中共有三个写工具。注册和权限测试不能证明医院接口已接通。检验工具使用请求提供的项目、数值、单位和参考范围，调用 LIS 解释接口；没有从 LIS 自动拉取整份患者检验记录的工具。

**三个专科默认调用同一个云端大语言模型。** 它们分别运行三个 A2A 服务，各自创建工具循环，维护本轮消息、工具结果、计数和去重记录。BERT 与 BGE-M3 是本地路由模型；规划、专科执行、汇总和按需语义复核使用配置的云端主模型。应用可院内部署，整条推理链当前仍有云调用。

## 4. 理解谁规划、谁行动

`MedicalCoordinator` 是流程调度程序。复杂任务时，`Planner.plan` 调用云模型生成最多三步计划，代码检查必要专科是否完整、无关或重复。结构不合法回退为受控计划，网络请求失败仍按失败结束。多个意图归同一专科时只调用该专科一次；用药审核等复杂单意图也可能先规划。

Planning 是协调器内部角色，最多三个专科的依赖计划：独立只读步骤并行，有前序依赖的步骤串行并传递脱敏依据；批准写动作时整体串行。非法依赖回退确定性短链。仅有一次只读覆盖纠错重路由，没有持久后台队列或任意节点断点恢复。

ReAct 是每个专科内部的“模型提出工具调用 → 程序校验执行 → 结果回填 → 决定下一步”循环。每个专科任务的模型和工具调用分别最多六次，同工具同参数重复调用被拦截。A2A 传任务，MCP 连接工具，Function Calling 表达模型调用请求；实际权限由代码校验。

专科重新读取可信患者档案，维护各自本轮执行循环。新任务隔离旧历史；待澄清续接只组合原任务和当前补充。依赖节点额外读取有界前序工具依据，协调器汇总，入口统一写回跨轮会话。A2A 回包须匹配任务、版本和步骤，配置 Redis 时 MCP 执行前检查任务活跃版本。

## 5. 理解写入、持久化与完成状态

三个 MCP 写工具是保存病史、另存辅助记录和创建转诊草稿。员工在本轮批准动作后才开放，服务端还检查角色与患者权限，转诊仅限医生。确认绑定动作类别，尚未绑定模型最后生成的全部参数。

写工具先校验参数，再按“员工、请求标识、工具名”登记唯一操作记录。相同键与参数已完成则复用结果；参数冲突、`pending` 或 `unknown` 则阻止重发。`GET /api/operations/{request_id}` 查询本地状态，医院实际结果另行核对。换请求标识仍可能重复，不能称为全局恰好一次。

档案编辑走独立 `PUT /api/patients/{patient_id}/profile`，医生或药师填写并保存。先 GET 读取 `revision`，PUT 必须携带 `expected_revision`；后端核对内容并用原字段 SQL 条件更新，旧版本返回 409，重载并核对后再保存。档案与修改字段名审计同事务提交，不使用聊天批准动作或 MCP 操作状态表。

关系数据库保存业务记录；Redis 保存近期历史、阶段记录与整轮锁，未配置时使用进程内过期缓存。会话键包含员工、患者和会话标识。阶段记录可定位中断位置，不能恢复任意模型工具循环。数据库先提交、会话后保存，两者没有跨存储事务。

**`delta` 是暂存片段，`done` 才是本轮分支的完成确认。** 汇总必须有实际内容并以 `finish_reason=stop` 正常结束，空白、仅免责声明、截断、过滤和缺少结束标记均失败。专科拒绝空回答和明确的非正常结束，但适配器缺少结束元数据时无法只靠该字段确认完整性。汇总失败不会进入正常答复保存，也不会撤销此前完成的 MCP 写工具。数据库提交后 Redis 失败，也不会回滚数据库。澄清或拒识可发送 `done`，但不表示原医学任务已完成。

## 6. 理解项目成果与追问口径

| 评测对象 | 留档结果 | 追问时应说清 |
|---|---|---|
| v4 合成数据 | 训练 3,100、验证 640、测试 1,340 | 阈值在验证集选；精确文本隔离不等于没有模板或语义泄漏 |
| 独立 BERT 合成测试 | 1,340/1,340 完整集合匹配 | 满分只对应这套合成任务，不能说临床准确率 100% |
| 独立 BERT 合成挑战 | 348/400=87%，Micro-F1 0.9461 | 多意图 243/250=97.2%，困难单意图 60/100，OOD 空集合拒识 45/50；挑战集已用于历次排错，并非新的盲测临床集 |
| 融合路由固定回归 | 2026-10-10 留档 33/33；28 条本地融合、5 条 LLM 复核 | 五条各重复三次为 15/15，不是十五个新样本；没有测医院工具或临床结论 |
| 工程回归 | 当前结果见 [README](../README.md#验证) | 包含应用、数据、部署和交付检查；数量不等于真实业务覆盖率 |

集合匹配要求预测标签不多不少；Micro-F1 汇总正标签的 TP、FP、FN，两者含义不同。历史健康接口约 401 RPS 不能作为完整 Agent 吞吐，旧 Softmax 阈值 0.95、旧向量残余成绩也不能用于描述当前融合版本。

模型、数据和原报告的指纹核对，以及换行差异统一见 [README 复核说明](../README.md#克隆后的模型准备与指标复核)。指纹一致证明字节相同，不证明最早生成时间、个人贡献或临床效果。历史过程见[修复与证据](intent-fusion.md#历史修复与证据)，上线缺口见[生产验收](production-readiness.md)。

面试收尾可以说：我重点做的是把自然语言任务变成有授权边界、真实工具依据和可核对状态的执行流程。工程机制已有回归证据，临床结论由医务人员复核，真实业务收益在医院试点中验收。
