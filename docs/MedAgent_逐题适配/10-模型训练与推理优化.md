## q-001

### 主问题｜RL 训练中如何防止 reward hacking？

原文位置：10-模型训练与推理优化.md 第 28 行（原件保存在同步前备份）。

**项目口述：** 这道是训练原理题：我的 MedAgent 没有运行强化学习训练，实际是本地 BERT 监督分类加云端模型调用。我会把 RL 方法作为后续工具选择策略的研究方案说明，不把文档中的算法当成已有项目成果。

**针对本题的设计展开（原文原理，作为方案解释）：**

reward hacking 指 policy（策略）找到奖励代理与真实目标之间的缺口，获得高 reward 却没有真正完成任务。它不只发生在 learned reward model，也可能利用规则奖励、格式奖励或环境实现漏洞。KL 只限制相对 reference（参考模型）的偏移幅度，不能证明策略没有利用奖励漏洞。

治理要围绕“奖励之外的独立真值”：优先使用可执行验证或业务结果；把 reward 开发集与对抗/保留集分开；检查 reward 上升时真实成功率、长度、格式和安全指标是否背离；对新策略产生的高分样本做人工或独立 verifier 审计；限制更新幅度并保留回滚。reward ensemble 只有在错误不高度相关时才有帮助，reject sampling 若仍使用同一个有漏洞的 reward 排序，反而可能放大 exploitation。

**在 MedAgent 中怎么补全：** 若用于院内工具选择，先用无真实写入的模拟环境和独立验收集，把任务完成、错误患者访问、错误写入和费用分别计分；高奖励不能代替临床目标完成。规则与权限不由奖励学习覆盖，训练出的策略仍要过现有执行守卫和人工复核。

**代码依据：** [scripts/train_intent_bert.py](../../scripts/train_intent_bert.py)、[backend/mcp_security.py](../../backend/mcp_security.py)、[backend/evidence.py](../../backend/evidence.py)

## q-007

### 主问题｜熵坍缩（entropy collapse）怎么检测和缓解？

原文位置：10-模型训练与推理优化.md 第 66 行（原件保存在同步前备份）。

**项目口述：** 这道是训练原理题：我的 MedAgent 没有运行强化学习训练，实际是本地 BERT 监督分类加云端模型调用。我会把 RL 方法作为后续工具选择策略的研究方案说明，不把文档中的算法当成已有项目成果。

**针对本题的设计展开（原文原理，作为方案解释）：**

熵坍缩指策略分布在 RL 过程中快速变尖，token-level policy entropy 持续下降，探索能力随之减弱。它不等于“回答措辞变少”：长度、模板化和 n-gram 多样性只能作为外部症状，核心仍要看训练策略在采样分布上的熵、KL、优势与奖励分布。

检测时同时监控平均 token entropy、不同位置/长度桶的熵、相对 reference 的 KL、同一 prompt 的有效回答数，以及 reward 上升但 pass@k 或保留集能力下降的背离。缓解应发生在训练环节：控制学习率和更新幅度、使用合适的 KL/clip/熵正则、修正奖励缩放和同分 group、提高训练数据与采样的有效多样性。单纯调高推理 temperature 只能让输出看起来更随机，不能修复已经坍缩的 policy。

**在 MedAgent 中怎么补全：** 若用于院内工具选择，先用无真实写入的模拟环境和独立验收集，把任务完成、错误患者访问、错误写入和费用分别计分；高奖励不能代替临床目标完成。规则与权限不由奖励学习覆盖，训练出的策略仍要过现有执行守卫和人工复核。

## q-010

### 主问题｜梯度饥饿（gradient starvation）怎么解决？

原文位置：10-模型训练与推理优化.md 第 82 行（原件保存在同步前备份）。

**项目口述：** 这道是训练原理题：我的 MedAgent 没有运行强化学习训练，实际是本地 BERT 监督分类加云端模型调用。我会把 RL 方法作为后续工具选择策略的研究方案说明，不把文档中的算法当成已有项目成果。

**针对本题的设计展开（原文原理，作为方案解释）：**

Gradient Starvation 原论文描述的是一种特征学习竞争：交叉熵可以依靠一小部分强预测特征迅速降低损失，使其他同样有预测力的特征几乎得不到继续学习的梯度。结果是模型依赖少数“捷径特征”，训练集准确率可能很好，但鲁棒性和分布外泛化变差。它不能直接等同于多任务中的 gradient conflict 或长尾样本占比不足。[Gradient Starvation 原论文](https://arxiv.org/abs/2011.09468)

治理要先验证模型是否只依赖某类特征：做特征消融、反事实/OOD 测试，比较强特征被遮蔽后的性能。方法上可采用论文提出的 spectral decoupling 一类正则化，或通过数据干预、反事实样本和表示约束削弱捷径特征的垄断。梯度裁剪、任务加权和均衡采样可以处理别的问题，但不是 Gradient Starvation 的定义性解法。

**在 MedAgent 中怎么补全：** 若用于院内工具选择，先用无真实写入的模拟环境和独立验收集，把任务完成、错误患者访问、错误写入和费用分别计分；高奖励不能代替临床目标完成。规则与权限不由奖励学习覆盖，训练出的策略仍要过现有执行守卫和人工复核。

### 主问题｜世界模型为什么可用 GVFs 构建？

原文位置：10-模型训练与推理优化.md 第 238 行（原件保存在同步前备份）。

**项目口述：** 这道是训练原理题：我的 MedAgent 没有运行强化学习训练，实际是本地 BERT 监督分类加云端模型调用。我会把 RL 方法作为后续工具选择策略的研究方案说明，不把文档中的算法当成已有项目成果。

GVF（General Value Function）把价值函数推广成由 policy、cumulant 和 continuation/discount 等要素定义的预测问题，可预测某个行为策略下未来信号的折扣累积期望。

一组 GVF 可以形成可查询、面向行为的预测知识，例如“执行某种策略后，传感器信号或某特征会怎样累积”。但这不自动等于一个足以规划的完整世界模型：OaK 还需要 action/option transition models，预测执行动作或 option 后的奖励、持续时间和状态特征变化。更准确的说法是：GVF 可作为世界知识的预测表示，并可用于定义/学习子任务；是否足够支撑规划取决于其预测集合和模型接口。

**在 MedAgent 中怎么补全：** 若用于院内工具选择，先用无真实写入的模拟环境和独立验收集，把任务完成、错误患者访问、错误写入和费用分别计分；高奖励不能代替临床目标完成。规则与权限不由奖励学习覆盖，训练出的策略仍要过现有执行守卫和人工复核。

### 主问题｜Token、上下文窗口、上下文腐化是什么？

原文位置：10-模型训练与推理优化.md 第 254 行（原件保存在同步前备份）。

原文位置：10-模型训练与推理优化.md 第 288 行（原件保存在同步前备份）。

**项目口述：** 模型通过 Function Calling 选择工具并生成结构化参数，LangChain 的 MCPAdapter 和 FastMCP 客户端通过 MCP 调用工具服务。FastMCP 注册 14 个工具，包括真实医院查询以及本地病史、辅助材料存储；服务端再次检查委托、员工状态、患者范围和写动作权限。两者在同一链路中使用。

**针对本题的设计展开（原文原理，作为方案解释）：**

样本通常是外部收集后交给模型的静态数据点，生成分布与当前 Agent 的行为未必有关；经验则来自 Agent 在环境中的连续闭环：观察状态、采取动作、看到后果并获得奖励。经验具有时间顺序、动作条件性和策略依赖性，Agent 变强后还能主动产生不同、可能更有价值的新经验。

因此“从经验学习”不只是把日志重新命名为训练集，而是让学习者参与数据生成，并面对探索、因果归因、非平稳性和安全交互问题。该观点属于研究主张，不应被写成已经证明的唯一通往通用智能的路线。[Silver 与 Sutton：Welcome to the Era of Experience](https://storage.googleapis.com/deepmind-media/Era-of-Experience%20/The%20Era%20of%20Experience%20Paper.pdf)

**在 MedAgent 中怎么补全：** 若用于院内工具选择，先用无真实写入的模拟环境和独立验收集，把任务完成、错误患者访问、错误写入和费用分别计分；高奖励不能代替临床目标完成。规则与权限不由奖励学习覆盖，训练出的策略仍要过现有执行守卫和人工复核。
